## 🔍 根本原因分析

### 问题1：后端月视图API的时区问题

**位置：** `backend/server_enterprise.js` 行1807-1810

**问题代码：**
```javascript
const currentDate = new Date(taskStartDate);
currentDate.setHours(0, 0, 0, 0);  // ⚠️ 问题！
const endDate = new Date(taskEndDate);
endDate.setHours(0, 0, 0, 0);  // ⚠️ 问题！
```

**问题原因：**
- `setHours(0, 0, 0, 0)` 会使用服务器的**系统时区**
- 如果服务器系统时区不是UTC+8，会导致日期计算错误
- 例如：系统时区是UTC时，`2025-10-26 14:00 CST` 会被当作 `2025-10-26 14:00 UTC`，导致日期偏移

**修复方案：**
```javascript
// 提取日期部分（避免时区问题）
const startYear = taskStartDate.getFullYear();
const startMonth = taskStartDate.getMonth();
const startDay = taskStartDate.getDate();
const endYear = taskEndDate.getFullYear();
const endMonth = taskEndDate.getMonth();
const endDay = taskEndDate.getDate();

// 使用本地时区的日期对象（仅包含日期，不含时间）
const currentDate = new Date(startYear, startMonth, startDay);
const endDate = new Date(endYear, endMonth, endDay);
```

### 问题2：前端周视图的时区解析问题

**位置：** `lib/widgets/calendar_widget.dart` 行743-761

**问题代码：**
```dart
taskStart = DateTime.parse(task.startTime!);  // ⚠️ 问题！
taskEnd = DateTime.parse(task.endTime!);      // ⚠️ 问题！

// 标准化日期
taskStart = DateTime(taskStart.year, taskStart.month, taskStart.day);
taskEnd = DateTime(taskEnd.year, taskEnd.month, taskEnd.day);
```

**问题原因：**
- Flutter的 `DateTime.parse()` 会将带时区的时间字符串转换为UTC时间
- 例如：`2025-10-26T14:00:00+08:00` → `2025-10-26 06:00:00.000Z` (UTC)
- 虽然日期部分还是26日，但如果后续处理不当，可能导致错误

**修复方案：**
```dart
// 从ISO 8601字符串直接提取日期（避免时区转换）
DateTime _extractDateFromISO(String isoString) {
  // 2025-10-26T14:00:00+08:00 -> 2025-10-26
  final datePart = isoString.split('T')[0];
  final parts = datePart.split('-');
  if (parts.length == 3) {
    return DateTime(
      int.parse(parts[0]),  // year
      int.parse(parts[1]),  // month
      int.parse(parts[2]),  // day
    );
  }
  // fallback
  final parsed = DateTime.parse(isoString);
  return DateTime(parsed.year, parsed.month, parsed.day);
}
```

## 📊 技术细节

### 为什么不能用setHours()?

```javascript
// ❌ 错误做法
const date = new Date('2025-10-26T14:00:00+08:00');
date.setHours(0, 0, 0, 0);
// 如果系统时区是UTC，会得到错误的日期

// ✅ 正确做法
const date = new Date('2025-10-26T14:00:00+08:00');
const newDate = new Date(date.getFullYear(), date.getMonth(), date.getDate());
// 直接创建新的Date对象，只包含年月日
```

### 为什么前端要提取日期字符串?

```dart
// ❌ 依赖DateTime.parse的时区转换
final date = DateTime.parse('2025-10-26T14:00:00+08:00');
// 会转换为UTC，然后再转换为设备本地时区

// ✅ 直接提取日期部分
final datePart = '2025-10-26T14:00:00+08:00'.split('T')[0];  // '2025-10-26'
final date = DateTime(2025, 10, 26);
// 明确指定日期，不依赖时区转换
```

### ISO 8601时间格式

```
2025-10-26T14:00:00+08:00
│          │          └─ 时区偏移：北京时间（UTC+8）
│          └─ 时间分隔符
└─ 日期部分（我们需要的）
```

## 🎉 修复总结

### 关键改进

1. **后端：避免使用 `setHours()`**
   - 直接提取年月日创建新Date对象
   - 不依赖系统时区

2. **前端：避免依赖 `DateTime.parse()` 的时区转换**
   - 直接从ISO字符串提取日期部分
   - 明确创建本地日期对象

3. **统一时区标记**
   - 所有API返回的时间都带 `+08:00` 标记
   - 确保前后端对时区的理解一致
