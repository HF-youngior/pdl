# 月视图数据问题修复说明

## 问题描述

用户反馈：每天打开项目后，在月视图里只能显示当天的日志和任务数据，明明昨天还可以显示所有数据的。

## 根本原因

经过诊断发现，问题的根源在于**数据插入脚本没有指定 `created_at` 字段**。

### 详细分析

1. **表结构现状**
   - `personal_logs` 表有一个 `created_at` 字段，类型为 `TIMESTAMP`
   - 该字段默认值为 `CURRENT_TIMESTAMP`
   - 后端月视图API通过 `created_at` 字段过滤日志数据

2. **原始数据插入方式**
   ```sql
   -- 旧的插入方式（有问题）
   INSERT IGNORE INTO personal_logs (id, user_id, title, content, ...) VALUES
   ('log-005', 'founder-001', 'Q1季度总结', '...', ...);
   ```
   - 没有指定 `created_at` 字段
   - MySQL自动使用 `CURRENT_TIMESTAMP`（当前时间）
   - 每次运行脚本，即使使用 `INSERT IGNORE`，如果数据被删除重新插入，`created_at` 都会变成新的当前时间

3. **后端查询逻辑**
   ```javascript
   // 月视图API查询
   WHERE pl.user_id = ?
   AND pl.created_at >= ?  // 基于创建时间过滤
   AND pl.created_at <= ?
   ```
   - 查询基于 `created_at` 字段
   - 如果所有日志的 `created_at` 都是今天，那么只有查询"今天"时才能看到数据

## 解决方案

修改数据插入脚本 `fixed_enhanced_data.sql`，**明确指定 `created_at` 字段为固定的历史日期**：

```sql
-- 修复后的插入方式
INSERT IGNORE INTO personal_logs (id, user_id, title, content, ..., created_at) VALUES
('log-005', 'founder-001', 'Q1季度总结', '...', ..., '2025-10-01 10:30:00'),
('log-006', 'founder-002', '产品发布会策划', '...', ..., '2025-10-02 14:15:00'),
('log-007', 'dept-head-001', '绩效考核方案', '...', ..., '2025-10-03 09:45:00'),
-- ... 等等，分布在10月的不同日期
```

### 修改的文件

1. **backend/fixed_enhanced_data.sql**
   - 在 INSERT 语句中添加 `created_at` 字段
   - 为每条日志指定不同的历史日期（2025年10月1日至18日）

2. **backend/reload_personal_logs.bat**（新增）
   - 删除现有日志数据
   - 重新加载修复后的数据
   - 方便用户快速应用修复

## 使用说明

如果遇到同样的问题（只能看到当天数据），请运行：

```bash
cd backend
reload_personal_logs.bat
```

这将：
1. 删除现有的测试日志数据
2. 重新加载修复后的数据（带有固定的历史日期）

## 注意事项

1. **`INSERT IGNORE` 的行为**
   - 如果主键已存在，不会插入新记录
   - 也不会更新现有记录的 `created_at`
   - 所以多次运行脚本是安全的，不会改变已有数据的日期

2. **为什么不修改后端查询逻辑？**
   - 当前表结构只有 `created_at` 字段，没有独立的 `log_date` 字段
   - 如果要彻底分离"业务日期"和"创建时间"，需要迁移表结构
   - 当前方案是最小改动的快速修复

3. **未来改进建议**
   - 考虑添加独立的 `log_date` 字段（业务日期）
   - `created_at` 保留为记录创建的时间戳
   - 查询时使用 `log_date` 而不是 `created_at`
