## 🎯 问题与解决

### 问题描述

**用户反馈：**
> "Q4绩效目标设定指导"任务的时间段在不同视图中显示不一致：
> - 数据库存储：2025-10-15 09:00 ~ 2025-10-17 17:00
> - 周视图显示：10月14-16日 ❌
> - 月视图显示：10月15-17日 ✅
> - 日视图显示：10月15-17日 ✅

### 根本原因

**时区标记缺失导致前端解析错误：**

1. MySQL存储：`2025-10-15 09:00:00`（无时区信息）
2. 后端返回：`2025-10-15T01:00:00.000Z`（被识别为UTC时间）
3. 前端解析：将UTC时间转换为本地时间，导致日期计算错误

**问题根源：** 后端返回的JSON中，时间字段没有明确标记时区

### 解决方案

**在后端API返回时，明确标记为北京时间（+08:00）**

修改后返回格式：`2025-10-15T09:00:00+08:00`

## 🔑 关键技术点

### 1. ISO 8601 时间格式

```
2025-10-15T09:00:00+08:00
│          │          └─ 时区：北京时间（UTC+8）
│          └─ 时间：09:00:00
└─ 日期：2025-10-15
```

### 2. 时区转换逻辑

```javascript
function formatDateTimeForBeijing(dateTime) {
  // 1. 接收Date对象或字符串
  // 2. 提取本地时间的各部分
  // 3. 组合成ISO 8601格式
  // 4. 明确标记+08:00时区
  return `${year}-${month}-${day}T${hours}:${minutes}:${seconds}+08:00`;
}
```

### 3. 前后端一致性

- **后端：** 明确返回 `+08:00` 时区标记
- **前端：** `DateTime.parse()` 正确识别时区
- **结果：** 所有视图的时间计算一致
