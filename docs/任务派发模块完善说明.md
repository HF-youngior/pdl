# 任务派发模块完善说明

## 📋 概述

本次更新完善了任务派发模块，使移动端和网页端都能创建任务并与数据库互通。

## 🎯 主要功能

### 1. 移动端任务创建
- **入口**：从四象限的右上角"公司派发的任务"模块进入，点击"+"按钮创建任务
- **权限控制**：管理员、团队长等具有创建任务权限的角色可以创建任务
- **数据流向**：创建的任务直接保存到数据库tasks表

### 2. 网页端任务创建
- **入口**：通过网页管理端的任务模块创建任务
- **功能**：支持创建任务并指派给指定用户
- **数据流向**：创建的任务保存到同一数据库tasks表

### 3. 数据互通
- 移动端和网页端创建的任务都存储在同一个数据库表中
- 任一平台创建的任务都能在另一平台查看

## 🔧 技术实现

### 1. 数据库模型修改

#### Task模型（lib/models/task.dart）
- 新增 `departmentId` 字段，用于与后端API匹配
- 修改 `toJson()` 方法，返回后端期望的下划线命名格式（`assignee_id`, `department_id`, `start_time`, `end_time`, `is_all_day`等）
- 修改 `fromJson()` 方法，支持从后端返回的数据中解析 `departmentId`

#### User模型（lib/models/user.dart）
- 新增 `departmentId` 字段，用于存储用户的部门ID
- 修改 `fromJson()` 方法，从后端返回的数据中获取 `department_id`
- 修改 `toJson()` 方法，同时返回驼峰式和下划线式命名

### 2. API服务更新

#### ApiService（lib/services/api_service.dart）
- 新增 `getUsers()` 方法，获取用户列表用于任务分配
- 新增 `getDepartments()` 方法，获取部门列表

### 3. 移动端代码修改

#### TaskEditScreen（lib/screens/task_edit_screen.dart）
- 在创建任务时使用当前用户的 `departmentId`
- 确保任务数据包含所有必需字段，与后端API匹配

### 4. 网页端代码修改

#### web_admin/app.js
- 修改 `createTask()` 函数，发送正确的数据格式给后端API
- 使用下划线命名格式（`assignee_id`, `department_id`等）
- 添加认证token支持，确保请求包含认证头

## 📊 数据流向

```
移动端创建任务
    ↓
Task.toJson() → 发送到后端API
    ↓
POST /api/tasks
    ↓
保存到tasks表（MySQL）
    ↓
网页端和移动端都能看到
```

```
网页端创建任务
    ↓
createTask() → 发送到后端API
    ↓
POST /api/tasks
    ↓
保存到tasks表（MySQL）
    ↓
网页端和移动端都能看到
```

## 🔑 关键字段说明

### 后端API期望的字段
- `title`: 任务标题
- `description`: 任务描述
- `assignee_id`: 被分配人ID（必需）
- `department_id`: 部门ID（必需）
- `priority`: 优先级（p0-p3）
- `deadline`: 截止时间
- `start_time`: 开始时间
- `end_time`: 结束时间
- `location`: 地点（可选）
- `is_all_day`: 是否全天任务

### 前端发送的字段
移动端和网页端都会发送上述字段给后端API，确保数据格式一致。

## 📝 使用说明

### 移动端创建任务
1. 登录系统（需要管理员或团队长权限）
2. 在主页点击右上角"公司派发任务"模块
3. 点击"+"按钮创建新任务
4. 填写任务基本信息（标题、描述、优先级等）
5. 设置任务时间（开始时间、结束时间、是否全天）
6. 选择任务进度并保存

### 网页端创建任务
1. 打开网页管理端
2. 点击"新建任务"按钮
3. 选择任务分配给的用户
4. 填写任务详细信息
5. 设置时间、地点等选项
6. 点击"发布任务"保存

## 🚨 注意事项

1. **权限控制**：只有具有创建任务权限的角色（管理员、团队长等）才能创建任务，普通员工无权创建任务
2. **必填字段**：任务标题和指派对象是必填项
3. **部门ID**：创建任务时必须提供有效的部门ID
4. **数据格式**：确保发送给后端的数据格式正确，使用下划线命名
