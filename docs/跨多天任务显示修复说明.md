# 跨多天任务显示修复说明

## 问题描述

之前的实现中，月视图和日视图只在任务的 `start_time` 所在日期显示任务。对于跨多天的任务（`start_time` 到 `end_time` 之间有多天），只会在开始日期显示，其他日期不显示。

**示例问题：**
- 任务"秋季校园招聘行程规划"从 2025-10-02 到 2025-10-04（共3天）
- 修复前：只在 10月2日 显示该任务
- 修复后：在 10月2、3、4日 都显示该任务

这导致月视图和日视图与周视图的甘特图数据不一致。

## 修复方案

### 1. 月视图 API 修复

**文件：** `backend/server_enterprise.js`

**修改位置：** 
- `/api/calendar/month-view` (认证API)
- `/api/month-view/:userId/:year/:month` (测试API)

**修复内容：**

1. **SQL查询优化**
   - 移除 `DISTINCT` 关键字（避免与 ORDER BY 冲突）
   - 保持原有的日期范围查询逻辑

2. **任务分配逻辑改进**
   - 原逻辑：只将任务添加到 `task_date`（开始日期）
   - 新逻辑：遍历任务的 `start_time` 到 `end_time` 之间的每一天，在每天都添加该任务

```javascript
// 新的任务分配逻辑
tasks.forEach(task => {
  // 确定任务的开始和结束日期
  let taskStartDate = null;
  let taskEndDate = null;
  
  if (task.start_time) {
    taskStartDate = new Date(task.start_time);
  }
  
  if (task.end_time) {
    taskEndDate = new Date(task.end_time);
  } else if (task.start_time) {
    // 如果没有 end_time，使用 start_time 作为结束日期
    taskEndDate = new Date(task.start_time);
  }
  
  // 如果任务有时间范围，在每一天都显示该任务
  if (taskStartDate && taskEndDate) {
    const currentDate = new Date(taskStartDate);
    currentDate.setHours(0, 0, 0, 0);
    const endDate = new Date(taskEndDate);
    endDate.setHours(0, 0, 0, 0);
    
    // 遍历任务跨越的每一天
    while (currentDate <= endDate) {
      const dateKey = `${currentDate.getFullYear()}-${String(currentDate.getMonth() + 1).padStart(2, '0')}-${String(currentDate.getDate()).padStart(2, '0')}`;
      
      if (calendar[dateKey]) {
        // 检查该任务是否已经添加到这一天（避免重复）
        const existingTask = calendar[dateKey].tasks.find(t => t.id === task.id);
        if (!existingTask) {
          calendar[dateKey].tasks.push({
            id: task.id,
            title: task.title,
            description: task.description,
            status: task.status,
            priority: task.priority,
            color: task.color,
            start_time: task.start_time,
            end_time: task.end_time,
            deadline: task.deadline,
            is_all_day: task.is_all_day,
            assignee_name: task.assignee_name
          });
          calendar[dateKey].hasData = true;
        }
      }
      
      // 移动到下一天
      currentDate.setDate(currentDate.getDate() + 1);
    }
  } else if (task.task_date) {
    // 如果没有时间范围但有 task_date，使用原来的逻辑
    const dateKey = task.task_date;
    if (calendar[dateKey]) {
      calendar[dateKey].tasks.push(taskObject);
      calendar[dateKey].hasData = true;
    }
  }
});
```

### 2. 日视图 API 修复

**文件：** `backend/server_enterprise.js`

**修改位置：** `/api/calendar/day-detail`

**修复内容：**

改进 SQL 查询，确保能获取跨越该日期的所有任务：

```sql
-- 原查询（不完整）
WHERE t.assignee_id = ?
AND (
  (t.start_time >= ? AND t.start_time <= ?)
  OR (t.end_time >= ? AND t.end_time <= ?)
  OR (t.deadline >= ? AND t.deadline <= ?)
  OR (DATE(t.start_time) = ? OR DATE(t.end_time) = ? OR DATE(t.deadline) = ?)
)

-- 新查询（完整）
WHERE t.assignee_id = ?
AND (
  -- 任务的开始时间在该日期
  (DATE(t.start_time) = ?)
  -- 任务的结束时间在该日期
  OR (DATE(t.end_time) = ?)
  -- 任务跨越该日期（开始时间在之前，结束时间在之后）
  OR (DATE(t.start_time) <= ? AND DATE(t.end_time) >= ?)
  -- deadline 在该日期
  OR (DATE(t.deadline) = ?)
)
```

**关键改进：**
- 新增条件：`DATE(t.start_time) <= ? AND DATE(t.end_time) >= ?`
- 这个条件能捕获跨越目标日期的任务（开始在之前，结束在之后）

## 影响范围

### 不受影响的功能

1. **周视图甘特图** - 本身就正确显示跨多天任务，无需修改
2. **任务列表** - 使用不同的查询逻辑，不受影响
3. **任务详情** - 单个任务查询，不受影响

### 受影响的功能

1. **月视图日历** ✅ 现在正确显示跨多天任务
2. **日视图** ✅ 现在正确显示跨越该日期的任务
3. **数据一致性** ✅ 三个视图（周、月、日）现在数据一致

## 注意事项

1. **性能考虑**
   - 对于跨越非常多天的任务（如30天以上），会在30个日期都添加该任务
   - 这可能会略微增加数据量，但不会影响性能（因为是内存操作）
   - 如有性能问题，可考虑前端分页或限制每天显示的任务数量

2. **边界情况**
   - 如果任务只有 `start_time` 没有 `end_time`，默认只在开始日期显示
   - 如果任务只有 `deadline` 没有 `start_time` 和 `end_time`，只在 deadline 日期显示
   - 这些行为与原逻辑保持一致

3. **日志输出**
   - 月视图API会输出每个任务添加到哪些日期的日志
   - 便于调试和监控

## 总结

此次修复确保了月视图、日视图和周视图的数据一致性，跨多天的任务现在会在所有相关日期正确显示，提升了用户体验和数据的准确性。
