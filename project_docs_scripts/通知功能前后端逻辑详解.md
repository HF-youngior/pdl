## 整体架构

### 连接方式
- **协议**: HTTP/HTTPS
- **认证方式**: Bearer Token (JWT)
- **数据格式**: JSON
- **轮询机制**: 前端每5秒轮询一次后端获取新通知

### 技术栈
- **后端**: Node.js + Express + MySQL
- **前端Flutter**: Dart + HTTP Client
- **前端Web**: JavaScript + Fetch API

## 后端逻辑

### 1. 通知创建函数 (`createNotification`)

**位置**: `backend/server_enterprise.js` 第3395行

```javascript
async function createNotification(taskId, fromUserId, toUserId, type, message) {
  try {
    const notificationId = require('crypto').randomUUID();
    await db.execute(
      'INSERT INTO task_notifications (id, task_id, from_user_id, to_user_id, notification_type, message) VALUES (?, ?, ?, ?, ?, ?)',
      [notificationId, taskId, fromUserId, toUserId, type, message]
    );
    return notificationId;
  } catch (error) {
    console.error('创建通知失败:', error);
    return null;
  }
}
```

**输入参数**:
- `taskId`: 任务ID（字符串）
- `fromUserId`: 发送者用户ID（字符串）
- `toUserId`: 接收者用户ID（字符串）
- `type`: 通知类型（字符串，如 'task_assigned', 'deadline_warning' 等）
- `message`: 通知消息内容（字符串）

**输出**:
- 成功: 返回通知ID（UUID字符串）
- 失败: 返回 `null`

**数据库表结构** (`task_notifications`):
- `id`: 通知ID（主键，UUID）
- `task_id`: 关联的任务ID
- `from_user_id`: 发送者用户ID
- `to_user_id`: 接收者用户ID
- `notification_type`: 通知类型
- `message`: 通知消息
- `is_read`: 是否已读（布尔值，默认false）
- `created_at`: 创建时间（时间戳）

### 3. 后端API接口

#### 3.1 获取通知列表
**端点**: `GET /api/notifications`  
**位置**: `backend/server_enterprise.js` 第2819行

**请求**:
- **方法**: GET
- **Headers**: 
  - `Authorization: Bearer {token}`
  - `Content-Type: application/json`
- **参数**: 无（通过token获取当前用户ID）

**处理逻辑**:
```javascript
app.get('/api/notifications', authenticateToken, async (req, res) => {
  const [rows] = await db.execute(
    `SELECT tn.*, t.title as task_title, t.deadline as task_deadline, u.name as from_user_name
     FROM task_notifications tn
     LEFT JOIN tasks t ON tn.task_id = t.id
     LEFT JOIN users u ON tn.from_user_id = u.id
     WHERE tn.to_user_id = ?
     ORDER BY tn.created_at DESC`,
    [req.user.id]
  );
  
  // 时间格式转换为北京时间
  const formattedRows = rows.map(row => {
    const formatted = { ...row };
    if (row.created_at) {
      formatted.created_at = formatDateTimeForBeijing(row.created_at);
    }
    if (row.task_deadline) {
      formatted.task_deadline = formatDateTimeForBeijing(row.task_deadline);
    }
    return formatted;
  });
  
  res.json(formattedRows);
});
```

#### 3.3 删除通知
**端点**: `DELETE /api/notifications/:id`  
**位置**: `backend/server_enterprise.js` 第2927行

**请求**:
- **方法**: DELETE
- **Headers**: 
  - `Authorization: Bearer {token}`
- **路径参数**: `id` (通知ID)

**处理逻辑**:
```javascript
app.delete('/api/notifications/:id', authenticateToken, async (req, res) => {
  const { id } = req.params;
  
  // 验证通知是否属于当前用户
  const [notificationRows] = await db.execute(
    'SELECT to_user_id FROM task_notifications WHERE id = ?',
    [id]
  );
  
  if (notificationRows.length === 0) {
    return res.status(404).json({ error: '通知不存在' });
  }
  
  if (notificationRows[0].to_user_id !== req.user.id) {
    return res.status(403).json({ error: '无权删除此通知' });
  }
  
  await db.execute('DELETE FROM task_notifications WHERE id = ?', [id]);
  res.json({ message: '通知删除成功' });
});
```

#### 1.3 通知轮询机制

**位置**: `lib/screens/dashboard_screen.dart` 第134-191行

**实现**:
```dart
void _startNotificationPolling() {
  _notificationPollingTimer?.cancel();
  if (_isGuestUser) return;
  _checkNotifications();
  // 每5秒检查一次新通知
  _notificationPollingTimer = Timer(const Duration(seconds: 5), _scheduleNextNotificationCheck);
}

Future<void> _checkNotifications() async {
  if (!mounted || _isGuestUser || !_settings.notificationsEnabled || _isCheckingNotifications) {
    return;
  }
  
  _isCheckingNotifications = true;
  try {
    // 1. 获取所有通知
    final notifications = await NotificationService.getNotifications();
    
    // 2. 更新未读通知数量
    final unreadCount = notifications.where((n) => !n.isRead).length;
    setState(() {
      _unreadNotificationCount = unreadCount;
    });
    
    // 3. 筛选出未读且未显示过的通知
    final newNotifications = notifications
        .where((n) => !n.isRead && !_displayedNotificationIds.contains(n.id))
        .toList();
    
    // 4. 显示新通知弹窗
    if (newNotifications.isNotEmpty) {
      for (final notification in newNotifications) {
        _displayedNotificationIds.add(notification.id);
      }
      await _showNotificationDialog(newNotifications);
    }
  } catch (e) {
    debugPrint('检查通知失败: $e');
  } finally {
    _isCheckingNotifications = false;
  }
}
```

**流程**:
1. 应用启动时开始轮询（每5秒一次）
2. 调用 `NotificationService.getNotifications()` 获取通知
3. 更新未读通知数量（显示在通知图标上）
4. 筛选出未读且未显示过的通知
5. 显示通知弹窗（只显示一次，避免重复）
6. 记录已显示的通知ID，避免重复弹窗

**去重机制**: 使用 `Set<String> _displayedNotificationIds` 记录已显示过的通知ID

```javascript
async function checkNotifications() {
    if (!authToken || !currentUser) return;
    
    try {
        // 1. 获取通知列表
        const response = await fetch(`${API_BASE_URL}/notifications`, {
            headers: getAuthHeaders()
        });
        
        if (!response.ok) return;
        
        const notifications = await response.json();
        
        // 2. 筛选未读通知
        const unreadNotifications = notifications.filter(n => !n.is_read);
        let hasNew = false;
        
        // 3. 检查是否有新通知（未显示过的）
        unreadNotifications.forEach(notification => {
            if (!pendingNotifications.some(item => item.id === notification.id) && 
                !displayedNotificationIds.has(notification.id)) {
                pendingNotifications.push(enhanceNotification(notification));
                hasNew = true;
            }
        });

        // 4. 如果有新通知且弹窗未打开，打开通知中心
        if (hasNew && !notificationModalInstance) {
            openNotificationCenterModal();
        }

        // 5. 更新通知徽章
        if (hasNew) {
            updateNotificationBadge();
        }
    } catch (error) {
        console.error('检查通知失败:', error);
    }
}
```

## 数据流转

### 完整流程示例：任务分配通知

```
1. 用户A创建任务并分配给用户B
   ↓
2. 后端接收创建任务请求
   ↓
3. 后端调用 createNotification(taskId, userA.id, userB.id, 'task_assigned', '您收到了新任务：xxx')
   ↓
4. 后端将通知插入数据库 task_notifications 表
   ↓
5. 用户B的前端每5秒轮询 GET /api/notifications
   ↓
6. 后端返回用户B的所有通知（包括新通知）
   ↓
7. 前端解析通知数据，创建 TaskNotification 对象
   ↓
8. 前端检查是否有未读且未显示过的通知
   ↓
9. 如果有，显示通知弹窗
   ↓
10. 用户点击"标记为已读"
    ↓
11. 前端调用 PUT /api/notifications/{id}/read
    ↓
12. 后端更新数据库 is_read = TRUE
    ↓
13. 前端更新UI，通知不再显示为未读
```

| POST | `/api/notifications/deadline-reminders` | 触发截止时间提醒 | `server_enterprise.js:2851` |

### 认证方式

所有接口都需要在请求头中携带JWT token:
```
Authorization: Bearer {token}
```

Token通过登录接口获取，存储在：
- **Flutter**: `ApiService._authToken`
- **Web**: `localStorage.getItem('authToken')`

## 总结

### 发送通知的流程
1. **触发点**: 各种业务操作（创建任务、完成任务、更新进度等）
2. **创建函数**: `createNotification()` 将通知写入数据库
3. **存储**: 通知保存在 `task_notifications` 表中

### 接收通知的流程
1. **轮询**: 前端每5秒调用 `GET /api/notifications`
2. **筛选**: 筛选出未读且未显示过的通知
3. **显示**: 显示通知弹窗或更新通知中心
4. **标记**: 用户操作后标记为已读

### 关键连接点
- **API端点**: `/api/notifications` (所有通知操作)
- **认证**: Bearer Token (JWT)
- **数据格式**: JSON
- **轮询机制**: 5秒间隔

### 输入输出总结

**发送通知（后端）**:
- **输入**: taskId, fromUserId, toUserId, type, message
- **输出**: notificationId (UUID)

**接收通知（前端）**:
- **输入**: 无（通过token自动获取）
- **输出**: List<TaskNotification>

**标记已读**:
- **输入**: notificationId
- **输出**: 成功/失败 (bool)
