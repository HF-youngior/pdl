## 权限控制机制说明

### checkPermission中间件
系统使用 `checkPermission` 中间件来验证用户权限：

```javascript
function checkPermission(requiredRoles) {
  return (req, res, next) => {
    if (!req.user || !requiredRoles.includes(req.user.role)) {
      return res.status(403).json({ error: '权限不足' });
    }
    next();
  };
}
```

### 管理员专用接口
以下接口需要 `admin` 或 `founder` 权限：
- `GET /api/admin/dashboard-stats` - 管理员仪表盘统计
- `POST /api/users` - 创建用户
- `GET /api/company-important-items/all` - 获取所有重要事项
- `POST /api/company-important-items` - 创建重要事项
- `GET /api/admin/search-users` - 搜索用户（仅admin）
- `GET /api/admin/user-statistics` - 获取用户统计（仅admin）

### 数据过滤机制
`GET /api/users` 接口使用数据过滤实现权限控制：
- `admin`/`founder`: 可以看到所有用户
- `department_head`: 只能看到本部门用户
- `team_leader`: 只能看到本团队用户
- `employee`: 只能看到自己

这不是越权问题，而是合理的数据访问控制。

## 注意事项

1. **HTTPS证书**: 如果使用HTTPS，Postman可能需要关闭SSL证书验证（仅用于测试）
2. **Token格式**: Authorization header格式必须为 `Bearer <token>`，注意Bearer后面有空格
3. **测试用户**: 测试用户 `test_employee` 已创建，可以直接使用
4. **服务器状态**: 确保服务器正在运行在端口8080

## 故障排除

### 问题1: 登录返回401错误
- 检查用户名和密码是否正确
- 确认测试用户已创建（运行 `node create_test_user.js`）

### 问题2: 访问接口返回401错误
- 检查Token是否正确复制（没有多余空格）
- 确认Authorization header格式正确：`Bearer <token>`

### 问题3: 访问管理员接口返回200（不应该）
- 这是安全漏洞！需要检查权限控制中间件是否正确应用
- 检查接口路由是否使用了 `checkPermission(['admin', 'founder'])`

### 问题4: 无法连接到服务器
- 确认服务器正在运行
- 检查端口8080是否被占用
- 检查防火墙设置
- 如果使用HTTPS，确认URL使用 `https://` 而不是 `http://`
