# 身份认证安全测试指南

## 测试目标
验证JWT Token过期机制是否正常工作。当Token过期后，系统应拒绝访问并返回相应的错误信息。

## 测试环境
- **服务器端口**: 8080
- **API基础URL**: `http://localhost:8080/api` 或 `https://localhost:8080/api`
- **Token过期时间**: 10秒（已修改用于测试）

## 测试步骤

### 步骤1: 修改Token过期时间（已完成）
✅ 已将 `backend/server_enterprise.js` 中的Token过期时间从 `'24h'` 修改为 `'10s'`

**修改位置**: `backend/server_enterprise.js` 第1280行
```javascript
{ expiresIn: '10s' }  // 测试模式：10秒过期
```

### 步骤2: 启动服务器
确保后端服务器正在运行：

```bash
cd backend
node server_enterprise.js
```

或者使用启动脚本：
```bash
cd backend
start_enterprise_backend_correct.bat
```

**验证服务器启动**:
- 看到 "HTTPS Server running on port 8080" 或类似消息
- API地址: `https://localhost:8080/api`

### 步骤3: 在Postman中登录获取Token

#### 3.1 创建登录请求
1. 打开Postman
2. 创建新请求，命名为 "登录 - 获取Token"
3. 设置请求方法: **POST**
4. 设置URL: `http://localhost:8080/api/auth/login` 或 `https://localhost:8080/api/auth/login`
5. 在 **Headers** 标签页添加:
   - Key: `Content-Type`
   - Value: `application/json`
6. 在 **Body** 标签页:
   - 选择 **raw**
   - 选择 **JSON**
   - 输入以下内容:
   ```json
   {
     "username": "hyx",
     "password": "hyx123"
   }
   ```
   或者使用其他测试账户:
   ```json
   {
     "username": "admin",
     "password": "admin123"
   }
   ```

#### 3.2 发送登录请求
1. 点击 **Send** 按钮
2. 查看响应，应该返回类似以下内容:
   ```json
   {
     "message": "登录成功",
     "user": {
       "id": "...",
       "username": "hyx",
       "name": "hyx",
       ...
     },
     "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
   }
   ```

#### 3.3 保存Token
1. 复制响应中的 `token` 值
2. 在Postman中创建环境变量或集合变量:
   - 点击右上角的 **Environments** 或 **Variables**
   - 创建新变量 `auth_token`
   - 将复制的token值粘贴进去
   - 或者直接在后续请求中使用复制的token

### 步骤4: 立即测试获取用户信息（验证Token有效）

#### 4.1 创建获取用户信息请求
1. 创建新请求，命名为 "获取用户信息 - Token有效"
2. 设置请求方法: **GET**
3. 设置URL: `http://localhost:8080/api/user/profile` 或 `https://localhost:8080/api/user/profile`
4. 在 **Headers** 标签页添加:
   - Key: `Authorization`
   - Value: `Bearer <你的token>` (将 `<你的token>` 替换为步骤3.2中获取的token)
   - 或者使用变量: `Bearer {{auth_token}}`

#### 4.2 发送请求
1. 点击 **Send** 按钮
2. **预期结果**: 
   - 状态码: `200 OK`
   - 响应体包含用户信息:
   ```json
   {
     "id": "...",
     "username": "hyx",
     "name": "hyx",
     "position": "员工",
     ...
   }
   ```

✅ **验证点**: 如果返回200和用户信息，说明Token当前有效。

### 步骤5: 等待Token过期后再次测试

#### 5.1 等待15秒
1. 记录当前时间
2. **等待至少15秒**（Token在10秒后过期，等待15秒确保已过期）
3. 可以使用手机计时器或Postman的延迟功能

#### 5.2 再次发送获取用户信息请求
1. 使用**相同的Token**（不要重新登录）
2. 发送相同的GET请求到 `/api/user/profile`
3. 确保Authorization header中的token是步骤3.2中获取的旧token

#### 5.3 验证过期响应
**预期结果**:
- 状态码: `403 Forbidden`
- 响应体:
  ```json
  {
    "error": "无效的访问令牌"
  }
  ```

✅ **验证点**: 如果返回403错误，说明Token过期机制正常工作！

### 步骤6: 重新登录获取新Token（可选验证）

#### 6.1 重新登录
1. 再次发送登录请求（步骤3）
2. 获取新的Token

#### 6.2 使用新Token测试
1. 使用新Token立即访问 `/api/user/profile`
2. **预期结果**: 返回200和用户信息
3. 等待15秒后再次访问
4. **预期结果**: 返回403错误

## 注意事项

1. **时间同步**: 确保服务器和客户端时间同步，Token过期基于服务器时间
2. **HTTPS vs HTTP**: 如果服务器使用HTTPS，确保Postman中URL使用 `https://`
3. **证书验证**: 如果使用HTTPS，可能需要在Postman设置中关闭SSL证书验证（仅用于测试）
4. **Token格式**: Authorization header格式必须为 `Bearer <token>`，注意Bearer后面有空格

## 故障排除

### 问题1: 登录后立即返回403
- 检查服务器时间是否正确
- 检查Token是否正确复制（没有多余空格）

### 问题2: 等待15秒后仍然返回200
- 确认代码修改已生效（重启服务器）
- 检查是否使用了新的Token（可能重新登录了）

### 问题3: 无法连接到服务器
- 确认服务器正在运行
- 检查端口8080是否被占用
- 检查防火墙设置
